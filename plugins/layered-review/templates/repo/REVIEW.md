# REVIEW.md

レビューする人（AI も人も）向けの、このリポジトリで何が大事かの決まり。**短く保つ。** 同じ指摘がくり返し出るなら、ここか lint かテストに足して、元から断つ。

## このプロダクトで「壊れた」とは

<!-- 利用者やお金やデータに響くことを、具体的に書く。例:
- 利用者のデータが消える・他人に見える
- 課金の状態とアプリの表示が食い違う
- 文書や機能マスタの内容が、実装と違う（嘘をつく）
- 設定が間違った先に向く（本番の API に開発用のキー など）
-->

## 指摘しないこと

- 書き方の好み、フォーマット（formatter と lint が見る）
- 変更していない行の問題は、`Pre-existing` として分けて出し、作者に直させない
- 名前の付け方は、取り違えを招くときだけ

## 見なくてよいパス

<!-- 例: 生成物・ロックファイル・スナップショット
- `**/generated/**`
- `package-lock.json`
-->

## 指摘の形

- すべての指摘に `path:line` を付ける。ファイル名を推測しない
- 「どんな入力・状況で、何が起きるか」を書く。書けないものは指摘にしない
- 同じ種類のバグがいくつもあれば、種類としてまとめて書き、全部の場所を挙げる（1 行ずつ直させない）
- 最初に要約を置き、件数（Important / Nit / Pre-existing）を書く。問題がなければ「指摘なし」と書く
