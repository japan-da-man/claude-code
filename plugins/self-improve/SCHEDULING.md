# 日時で動かす（未検証）

自動改善と棚卸しの候補出しを、Claudeデスクトップアプリのスケジュール済みタスクで日時どおりに動かす手順です。

- **未検証です。** 手順は公式ドキュメントをもとに書いたもので、実機で通していません。アプリの画面や項目名は変わることがあります。最初の1回は手動で実行して確かめてください。
- **なくても動きます。** タスクを設定しない場合や、実行を逃した場合は、間隔（`auto.interval_days`）を過ぎた時点でセッション開始時に知らせます。その場でスキルを呼べば同じことができます。

| タスク | 呼ぶスキル | 位置づけ | 日時の例 |
| --- | --- | --- | --- |
| 自動改善 | `/self-improve:auto-improve` | 本編（設計書4章） | 毎週月曜の9時 |
| 棚卸しの候補出し（**未実装（ステップ4）**） | `/self-improve:harness-prune` | 任意（設計書13章） | 毎月1日の10時 |

日時はタスクの側で決めます。`harness/config.json` には間隔（`auto.interval_days`、`prune.interval_days`）だけを書きます。

## 知っておくこと

- ローカルのタスクは、アプリが開いていて、マシンが起きているときだけ動きます。
- 予定の時刻から数分遅れて始まります。
- 逃した実行は、あとで起動したときに1回だけ追いかけて実行されます（7日以内の分）。月曜9時のタスクが、火曜の夜に動くこともあります。
- 追いかけの実行と手動の実行が重なっても、二重には動きません。前回の実行から、間隔の半分（7日なら3.5日）がたっていないとき、`auto-improve` は何もせずに終わります。
- 追いかけの実行や手動の実行のあとでも、次の定時の実行は飛びません。たとえば、月曜9時の分が火曜の夜に動いても、次の月曜9時（5日半後）には実行されます。間隔を、タスクの周期と同じ日数（毎週なら7）にしておいてください。
- **確認が出ると、タスクはそこで止まって待ちます。** 拒否にはなりません。止まったときは、タスクの履歴からその実行のセッションを開いて、確認に答えます。
- 改善候補と試用はマシンごとに別なので、タスクは普段作業しているマシンで設定します。クラウド側の定期実行は、これらが読めないため使いません。

## 自動改善が止まらないようにする仕組み

自動改善は、`harness-note` コマンドを通してしか書き込みません。ファイルを直接編集することはありません。そのため、必要な許可は1つだけです。

1. ユーザー設定（`~/.claude/settings.json`）に、次の許可ルールを足します。スケジュール済みタスクのセッションにも効きます。（`auto-improve` スキルの `allowed-tools` にも同じ許可を書いてありますが、スキルの呼ばれ方によっては効かないことがあるので、ユーザー設定にも置きます。）

   ```json
   {
     "permissions": {
       "allow": ["Bash(harness-note *)"]
     }
   }
   ```

2. 自動改善のセッションで通るツールは、Read、Grep、Globと、Bashの `harness-note` だけです。それ以外（Write、Edit、ほかのBash、MCPのツール、サブエージェントの起動、Webの取得、ほかのスキルの呼び出しなど）は、プラグインのガードが拒否します。確認は出ません。検証（`verify`）も動きません。作業途中のコードを無人で触らないためです。
   - `harness-note` は、そのセッションのIDと一致する `--session` が付いた、単純な呼び出しだけが通ります。`cat`・`ls`・`git log` のような読むだけのBashも通りません（読むのは Read・Grep・Glob）。
   - この制限は、プラグインのhookが動いていることが前提です（サンドボックスではありません）。下の手順6のとおり、権限の確認を省略するモードは選ばないでください。
   - 自動改善を実行したセッションは、終わったあとも書き込みに確認が挟まり、`harness-note` での試用の追加や確認の記録は見送りになります。タスクのセッションを、ほかの作業に使い回さないでください。確認（`/self-improve:review`）は、別のセッションで行います。
   - 自動改善が動いているあいだは、ほかのセッションからの試用の追加や確認も見送りになります。終わってから、やり直してください。

## 自動改善（`harness-auto-weekly`）

### 設定手順

1. `harness/config.json` の `auto.interval_days` を7にします。
2. 上の許可ルールを、ユーザー設定に足します。
3. デスクトップアプリでスケジュール済みタスクの画面を開き、新しいタスクを作ります。「このコンピュータだけ」で動かす設定にします。
4. フォルダに、適用先のリポジトリを指定します。Worktreeは選びません。作業フォルダにある今のルールと照らし合わせるためです。
5. スケジュールは「毎週」を選び、曜日と時刻を決めます。
6. 権限モードは、確認を出すモードのままにします。ファイルの編集を自動で許可する必要はありません。権限の確認をすべて省略するモードは選びません。
7. 下のプロンプトを貼り付けます。
8. 「今すぐ実行」で1回動かし、確認が出ないかを見ます。出た場合は、内容を確かめてから対応を決めます（下の「手動実行で確かめること」）。

### プロンプト

規則はスキルの側に書いてあります。プロンプトは短くします。

```text
このリポジトリで、self-improve プラグインの auto-improve スキルを実行してください。

- ファイルを直接編集しないでください。書き込みは harness-note コマンドだけを使います。
- コミットとプッシュはしないでください。
- harness/config.json がないとき、前回の実行から間隔がたっていないとき、対象の候補がないときは、何もせずに終了してください。
- 最後に、追加・編集・案の件数を1行で報告してください。
```

### 動いたかの確かめ方

次のセッションを始めると、報告が出ます。報告は、`/self-improve:review` を開くか、知らせを閉じるまで、セッションを始めるたびに出ます（閉じなくても7日で出なくなります）。ほかのスケジュール済みタスクや `claude -p` のような無人のセッションが先に始まっても、報告は消えません。確認が済むまでは、未確認の件数の1行が出ます。

試用ルールと実行の記録は、リポジトリの外（プラグインのデータ領域）にあります。`git status` には何も出ません。

### 手動実行で確かめること

未検証の点です。「今すぐ実行」で確かめてください。

- [ ] タスクのセッションで、プラグインのスキルとhookが動くか
- [ ] `harness-note` の実行に確認が出ないか
- [ ] `harness-note` が、プラグインのデータ領域と `~/.claude/skills/` に確認なしで書けるか
- [ ] タスクのセッションから、普段のセッションと同じ改善候補と事象メモが読めるか
- [ ] ファイルを直接編集しようとしたとき、確認ではなく拒否になるか。`harness-note` 以外のBash、MCPのツール、サブエージェントの起動も拒否になるか
- [ ] 次のセッション開始時に報告が出るか。`/self-improve:review` を開くまで出続けるか
- [ ] 作った試用Skillが、次のセッションで読み込まれるか
- [ ] スキルの中の `harness-note … --session …` に入るセッションIDが、hookに渡る `session_id` と一致するか（一致しないと、`harness-note` の呼び出しがすべて拒否され、何も書かれずに終わります）
- [ ] サブエージェントのツール呼び出しにも、ガード（PreToolUse）が効くか
- [ ] 「今すぐ実行」のあと、次の定時の実行が飛ばないか（Claudeに `harness-note status` を実行してもらうと、「次に実行できるのは … 以降」と出ます）

## 棚卸しの候補出し（`harness-prune-monthly`、任意）

**未実装（ステップ4）です。** `harness-prune` スキルがまだないので、このタスクはまだ設定できません。下は、実装したあとの手順です。

自動で行うのは、候補の一覧をレポートに書き出すところまでです。残すか消すかは、あとで人が `/self-improve:harness-prune` を呼んで決めます。前提は、`harness-prune` が実装済みであること（設計書11章のステップ4）です。

このタスクは、リポジトリの中の `harness/reports/` に書き込みます。権限モードは、ファイルの編集を自動で許可するものを選びます。スケジュールは「カスタム」にして、cron式で `0 10 1 * *`（毎月1日の10時）のように書きます。cron式は、マシンの現地時刻で解釈されます。

### プロンプト

```text
このリポジトリで、self-improve プラグインの harness-prune スキルを「一覧だけ」で実行してください。

やること
- 棚卸しの候補を一覧にする
- 一覧を harness/reports/prune-candidates-YYYY-MM.md に書き出す（YYYY-MM は今月）
- 候補が0件でも、「候補なし」と書いたレポートを残す

やらないこと
- ルール、Skill、ガード、harness/config.json、失敗票の変更や削除
- コミット、プッシュ
- 確認が必要な操作

harness/config.json がないリポジトリでは、何もせず終了してください。
最後に、候補の件数とレポートのパスを1行で報告してください。
```

この一覧は、棚卸しの「実行済み」には数えません。人が選んだ結果を書いたレポート（`prune-YYYY-MM.md`）ができるまで、間隔を過ぎた通知は出続けます。

### 動いたかの確かめ方

```bash
ls harness/reports/          # prune-candidates-YYYY-MM.md があるか
```

## やめるとき

タスクを削除し、`config.json` の該当する `interval_days` を0にします。0にすると、「間隔を過ぎています」の通知も出なくなります。
