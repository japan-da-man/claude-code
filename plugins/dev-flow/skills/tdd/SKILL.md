# tdd: テスト駆動で進める

振る舞い 1 つにつき、次の 3 手を回す。**1 周は小さく**（数分で終わる大きさ）。

## 0. 準備

- このリポジトリのテストの書き方と実行コマンドを確かめる（既存のテスト、`package.json` の scripts、`Makefile`、CLAUDE.md）。既存の流儀に合わせる。
- テストの実行は、出力が長くなりそうなら サブエージェント `dev-flow:test-runner` に任せる。
- 最初に既存のテストを一度流し、**今は通っていること**を確かめる（落ちていたら、それはこの作業のせいではないと分かるように報告する）。

## 1. RED: 失敗するテストを書く

- 実装しようとしている**振る舞い**を 1 つだけ、テストにする。
- 実行して、**期待した理由で失敗すること**を確かめる。文法エラーや import 漏れで落ちているのは RED ではない。
- バグ修正なら、まず**そのバグを再現するテスト**を書き、落ちることを確かめる。

## 2. GREEN: 通す最小の実装

- テストを通す**最小の**コードだけ書く。先回りして一般化しない。
- 実行して、通ることを確かめる。他のテストも壊れていないこと。

## 3. REFACTOR: 整える

- 通ったまま、重複・名前・構造を整える。振る舞いは変えない。
- 整えるたびにテストを流す。

## 終わりに

- 追加したテストと、確かめた結果（流したコマンドと通った件数）を報告する。
- テストを書けなかった、あるいは流せなかったときは、その理由をそのまま書く。「通るはず」とは書かない。
