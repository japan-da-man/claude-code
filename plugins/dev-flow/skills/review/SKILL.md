# review: 差分レビュー

## 1. 対象を決める

- 引数なし：`git diff` と `git diff --staged`（なければ `git diff <base>...HEAD`）。
- PR 番号：`gh pr diff <番号>`。
- ブランチ・パス：その差分。

差分が小さい（目安 300 行未満）ならこの場で読む。大きいなら、サブエージェント `dev-flow:reviewer` に、観点ごと・ファイルのまとまりごとに分けて任せる（実装した本人とは別のコンテキストで見ることに意味がある）。

## 2. 見る観点

1. **正しさ**：意図どおり動くか。境界値、null、エラー経路、並行処理、後方互換。
2. **テスト**：変更した振る舞いにテストがあるか。テストが本当に失敗しうるか（何も確かめていないテストでないか）。
3. **セキュリティ**：入力検証、認証・認可、秘密情報の混入、インジェクション。
4. **過剰・重複**：既存コードで足りるのに新しく作っていないか。使っていないコード。
5. **読みやすさ**：名前、構造、コメントが「なぜ」を説明しているか。

差分に出ていない周辺（呼び出し元など）は、必要なら読んで確かめる。

## 3. 指摘の出し方

重要度の高い順に出す。各指摘に `path:line`、**何が問題か**、**どんな入力・状況で何が起きるか**、直し方の案を付ける。

- **must**：直さないとバグ・事故になる
- **should**：直したほうがよい（保守性・テスト不足）
- **nit**：好みの範囲（まとめて短く）

守ること:
- 確かめていないことを断定しない。推測は「推測」と書く。
- 問題がなければ「指摘なし」と言い、何を確かめたかを書く。無理に探さない。
- **このスキルでは修正しない。** 直すのは、ユーザーが頼んだあと。
