## 進め方

1. 仕様の振る舞いを 1 つずつ、テストを先に書いてから実装する（RED → GREEN）。
2. テストは振る舞いを確かめるものにする。期待値を決め打ちしたり、テストを弱めたりして通さない。
3. 終わったら、ビルドと全テストが通ることを確かめる。
   - ビルド: `{{build}}`
   - 全テスト: `{{test}}`
4. コミットはしなくてよい。終わったあとの作業ツリーを、ラインがそのままコミットして検証する（自分でコミットしてもよい。push はしない）。

## 道具の使い方

- ファイルを作る・変えるときは、Write と Edit を使う。Bash で `cat > ファイル <<EOF` のように書かない（許可されていない）。
- Bash は、1 回に 1 つのコマンドだけ実行できる。`&&`・`;`・パイプ・ヒアドキュメント・`cd` は使わない。使えるのは、ビルドとテストのコマンド（`xcodebuild`・`xcodegen`・`swift`）、`ls`、`git status`・`git diff`・`git log`・`git add`・`git commit` だけ。
- コマンドが拒否されても、Bash がすべて使えないわけではない。上の形に直して、もう一度実行する。**ビルドと全テストは、必ず自分で実行して通ることを確かめる。**
