# 共通の切り分け

どのアラートでも、まずこの順に確かめる。アラートごとの手順は、同じディレクトリの runbook に書く。

## 影響の確かめ方

1. いつから：最初のエラー・アラートの時刻。直前のデプロイ・設定変更・リリースはあるか
2. 誰に：全員か、特定の OS・バージョン・地域・プランか
3. どれだけ：エラーの数と割合、失敗している操作、問い合わせの数
4. 重要度を README の「重要度」で決め、`observability/incidents/YYYY-MM-DD-<name>.md` に記録を始める

## 切り分け

1. 変更：直前のデプロイ・リリース・フィーチャーフラグ・設定・依存しているサービスの障害情報
2. エラー監視：新しく出た・急に増えたエラー。スタックトレースと、最初に出たリリース
3. ログ：`trace_id` / `request_id` で 1 件の失敗を最後まで追う
4. メトリクス：レイテンシ・エラー率・飽和（CPU・メモリ・接続数・キュー）

## 対処

- まず影響を止める（ロールバック、フラグを切る、段階リリースを止める）。原因の修正はそのあと
- 外に影響する操作は、対応する人が実行し、時刻を記録に書く
