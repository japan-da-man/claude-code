# ログの決まり

ログは「あとで障害を切り分ける人」のために書く。読む人は、そのとき画面も利用者の操作も見ていない。

## レベル

| レベル | 使うとき | 本番で出すか |
| :- | :- | :- |
| error | 利用者の操作が失敗した・データが壊れうる。対応が要る | 出す（エラー監視にも送る） |
| warn | 失敗したが、やり直しや代わりで続けられた | 出す |
| info | 状態が変わった（ログイン、注文の確定、ジョブの完了） | 出す |
| debug | 開発のときだけ見たい細かいこと | 出さない |

## 必ず付ける項目

| 項目 | 意味 |
| :- | :- |
| `timestamp` | ISO 8601（UTC） |
| `level` | 上のレベル |
| `message` | 何が起きたか（固定の文。値は項目に分ける） |
| `service` / `app` | どのアプリ・サービスか |
| `version` | リリースの識別子 |
| `env` | production / staging / development |
| `trace_id` / `request_id` | 1 つの操作・リクエストをつなぐ ID |

<!-- モバイルなら session_id・os・device_model、サーバーなら route・status・duration_ms など、スタックに合わせて足す -->

## 書いてはいけないもの

- パスワード、トークン、API キー、Cookie、Authorization ヘッダー
- メールアドレス、電話番号、住所、氏名、生年月日、カード番号
- 利用者が入力した自由な文（検索語・メッセージ本文など）。必要なら長さや種類だけ
- 位置情報の細かい値

ロガーのマスキング（キー名で伏せる）で防ぎ、`observability/check.mjs` の禁止の書き方でも止める。
