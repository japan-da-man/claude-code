# QUESTIONS.md の書き方

質問は **段階（設計・実装）ごとにまとめて** 1 つのファイルに書く。人は「回答：」の行を埋めて、スキル（design）か同じ /goal（implement）を実行し直す。

```markdown
# 質問: <feature>

## 設計

### Q-1 レート制限の単位（blocking）
- 背景：要件に「上限を設ける」とだけあり、単位が書かれていない
- 選択肢：A. ユーザー単位 / B. API キー単位 / C. 両方
- 推奨：B（既存の認証ミドルウェアがキーを持っているため）
- 回答：

## 実装

### Q-2 …（non-blocking・仮定して進めた）
- 背景：…
- 選択肢：…
- 推奨：…（この案で進めた）
- 回答：
```

## blocking と non-blocking

- **blocking**：答えによって設計や実装の形が変わり、あとから直すと大きな手戻りになるもの。回答があるまで、その部分は進めない。
- **non-blocking**：推奨案で進めても、あとから小さく直せるもの。推奨案で進め、見出しに「仮定して進めた」と書き、PROGRESS.md の「仮定」にも残す。

## 決まり

- 番号（Q-1, Q-2 …）は通しで振り、消さない。答えが出た質問も残す（判断の記録になる）。
- 1 つの質問には 1 つの論点だけ。選択肢は 2〜4 個にして、必ず推奨を 1 つ書く。
- 推測で埋められることは質問にしない。コードや文書を読めば分かることは調べてから書く。
- 「回答：」が空の blocking が残っている間は、その段階を終わりにしない。
